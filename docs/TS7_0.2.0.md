# TS7Play 0.2.0

Version 0.2.0 adds Simplified Chinese and the original DiPlay operation and
connection-settings pages inside the TS7Play APK. The application ID remains
`com.hilllaoya.ts7play`; version code is 2 and minSdk remains 25.

The app does not require a separate DiPlay installation. Runtime accessory
authentication is still an independent input. The source-only APK contains no
such identity and cannot independently connect to an iPhone.

## Use

Install the update using the same signing key as version 0.1.0. Keep the original
vehicle launcher available. The app selects Simplified Chinese once during this
upgrade; later language choices made in DiPlay are retained.

- **DiPlay** in the sidebar opens the original DiPlay home page inside TS7Play.
- **Connect** opens that same page. Use its original USB/wireless connection
  controls and connection setup.
- **DiPlay settings** opens the original settings overview, including Connection,
  Display, Audio, startup options and Diagnostics.
- **Desktop settings** retains the original-launcher selector, default HOME
  selection and launcher diagnostics. After switching to DiPlay, receiver
  configuration is handled in the DiPlay pages.
- **Home** returns to the TS7 launcher. When DiPlay has a compatible active main
  display, that picture is attached to the desktop panel without a second decoder
  or a new connection.
- **Disconnect** on the desktop stops the active receiver through its owner.

The two shortcuts remain configurable. On compact screens their list can scroll;
the original-home, system-settings and desktop-settings controls remain fixed at
the bottom of the sidebar.

The original DiPlay interface includes its supported Wi-Fi modes, USB connection
setup, authentication-provider selection, display options, audio settings and
diagnostics. Device-specific vehicle controls retain upstream requirements and
are not evidence of TS7 hardware compatibility. The upstream updater is hidden
and its background scheduler is disabled in this hosted build because upstream
APKs have a different package/signing identity. Parked entertainment video remains
disabled, following the original TS7 scope.

## Connection migration and ownership

On the first entry to DiPlay, the legacy TS7 SSID, password, selected paired phone
and audio-focus preference are copied into DiPlay when an existing Wi-Fi
configuration is absent. Later DiPlay edits are not overwritten. Credentials stay
in private application preferences and are not included in diagnostics or source.
Pairing identities are not migrated between the two engines; an already paired
phone may need to be paired again when changing receiver modes.

An existing legacy desktop receiver is cancelled and fully closed before the
DiPlay page opens. The handoff callback is cancelled if the launcher leaves the
foreground. A process-local reservation blocks DiPlay from starting a concurrent
receiver during legacy creation or teardown. Conversely, the legacy receiver
cannot start while DiPlay owns a session or projection Activity. Opening DiPlay
disables the legacy auto-connect path and records the selected receiver mode.

DiPlay keeps ownership of its own controller, audio, reconnection behavior and
foreground service. The launcher borrows only the existing main Surface and
touch interface while visible. Returning to the original projection page restores
its Surface. The launcher polls its view state only while visible and never
launches another Activity from that polling loop.

The desktop preserves the active stream's aspect ratio and buffer dimensions.
The plain, unrotated main display can be embedded. Advanced rotated or multiple
view-area layouts remain in the original projection page; the desktop explicitly
directs the user there instead of sending incorrect touch coordinates.

## Build

Use the JDK 25, SDK 37.0, Build Tools 36.0.0 and NDK 28.2.13676358 setup from
[BUILD.md](BUILD.md).

```sh
./gradlew :ts7:testDebugUnitTest :ts7:lintDebug :ts7:assembleDebug
```

Output: `ts7/build/outputs/apk/debug/ts7-debug.apk`.

For an authenticated car-test build, provide valid external `offline-mfi`
runtime files through `DIPLAY_AUTH_ASSETS_DIR` and use
`:ts7:assembleStandaloneDebug`. Android signing material and runtime
authentication material remain separate. No private runtime material is included
in the repository.

## Verification boundaries

Local verification on 2026-10-29:

- The complete repository CI command passed: shared 1,798 tests (one skipped),
  common 1,734 tests, Home 11 tests and TS7 42 tests at that checkpoint.
- After the final launcher-intent and authentication-copy adjustments, all 44
  TS7 tests and all six integration-bridge tests passed. The TS7 lint and APK
  build tasks also passed; lint reported zero errors and seven warnings.
- The final manifest has one LAUNCHER Activity. Both `DiPlayActivity` and
  `CarPlayHostActivity` were verified in the APK's DEX files.
- APK signature verification passed, and its signing certificate matches the
  delivered 0.1.0 APK, allowing a same-package update.
- The source-only APK is 26,779,411 bytes. SHA-256:
  `31e9559c3f197056b85932263b88a118f5068ce379af83c1903c0ee0b221e890`.
- APK inspection confirmed that no runtime MFi identity or private-key
  containers are bundled.

Automated checks cover Chinese launcher text, opening the real bundled DiPlay
Activity, rendering its Connection/Display/Audio settings, exclusive receiver
reservations, asynchronous handoff cancellation, one-time configuration import,
supported display dimensions and unsupported-layout fallback. Native Robolectric
renders cover the Chinese desktop and settings at compact/full sizes and the
original DiPlay home/settings pages.

These checks do not establish successful iPhone authentication, actual video
playback, microphone routing, TS7 ACC wake, reverse-camera behavior or sustained
operation. The device checklist in [TS7_IMPLEMENTATION.md](TS7_IMPLEMENTATION.md)
still applies. No target car or iPhone was remotely connected during this work.

The APK now reuses the `:common` DiPlay UI as well as `:shared`. Retain the
[third-party notices](THIRD_PARTY_NOTICES.md), including the AGPL-derived UI
notices, with distribution and provide corresponding source.
